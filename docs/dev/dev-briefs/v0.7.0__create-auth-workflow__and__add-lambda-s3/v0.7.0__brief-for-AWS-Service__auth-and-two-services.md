# Brief for MGraph-AI Service AWS

**Version:** v0.1.0
**Created:** December 2025

## Document Purpose

This brief provides complete implementation guidance for creating the MGraph-AI__Service__AWS FastAPI service to expose AWS API capabilities (Lambda, S3, and future services) through a stateless, encrypted-credentials architecture.

**Target Audience**: LLM agents or developers implementing the service layer, routes, and schemas.

**Reference Codebase**: `the-cyber-boardroom/MGraph-AI__Service__AWS` (new repo)

**Sister Project**: `the-cyber-boardroom/MGraph-AI__Service__GitHub` (pattern reference)

## 1. Executive Summary

### 1.1 Project Context

The MGraph-AI Service AWS is a stateless microservice that proxies AWS API operations. It holds no secrets server-side—clients provide encrypted AWS credentials that are decrypted on-the-fly using NaCl keys that exist only in Lambda memory and rotate on each deployment.

This follows the same architectural pattern as MGraph-AI__Service__GitHub, adapted for AWS's multi-service, multi-region model.

### 1.2 Credential Model

**What gets encrypted** (sensitive):
- `secret_access_key` - Always encrypted
- `session_token` - Encrypted when present (STS temporary credentials)

**What stays plaintext** (for logging/debugging):
- `access_key_id` - Identifies the credential (not secret)
- `account_id` - Target AWS account
- `region` - Target AWS region

This split enables useful logging like "Request to account 123456789012 in us-east-1 using AKIA..." without exposing secrets.

### 1.3 Key Architectural Principles

1. **No GET requests** - All operations use POST/PUT/DELETE with request body
2. **Encrypted secrets in request body** - Only secret_access_key and session_token encrypted
3. **Stateless** - No server-side credential storage
4. **Multi-service** - Routes organized by AWS service (Lambda, S3, etc.)
5. **Region-aware** - Each request specifies target region
6. **Client provides everything** - Including assumed role credentials if needed

## 2. Architecture Decisions & Rationale

### 2.1 Partial Credential Encryption

**Decision**: Encrypt only `secret_access_key` and `session_token`. Keep `access_key_id`, `account_id`, and `region` in plaintext.

**Rationale**:
- `access_key_id` is not secret (appears in CloudTrail, IAM console, etc.)
- Plaintext metadata enables meaningful logging: "Lambda invoke for account X in region Y"
- Debugging is possible without decryption
- Reduces encryption overhead
- Matches AWS's own model where access_key_id is logged openly

**Request Structure**:
```
Schema__AWS__Request__Base
├── access_key_id              : str  (plaintext)
├── encrypted_secret_access_key: str  (NaCl encrypted, base64)
├── encrypted_session_token    : str  (NaCl encrypted, base64, optional)
├── account_id                 : str  (plaintext, optional - for validation)
├── region                     : str  (plaintext, default: us-east-1)
└── request_data               : Schema__Request__Data (operation-specific)
```

### 2.2 Client-Side Role Assumption

**Decision**: Server does not assume roles. Client provides all credentials including assumed-role credentials.

**Rationale**:
- Server has no AWS IAM permissions needed
- Client controls which roles they assume
- Simpler server architecture (just configures boto3 with provided creds)
- Works with any credential type: IAM User, STS, SSO, etc.

**Flow for assumed roles**:
1. Client assumes role locally (or has temporary creds from SSO/federation)
2. Client encrypts the temporary secret_access_key and session_token
3. Client sends request with all credential components
4. Server configures boto3 session with provided credentials
5. Server makes AWS API call

### 2.3 POST for All Operations

**Decision**: Use POST for all operations (list, get, describe). Use PUT for updates. Use DELETE for removals.

**Rationale**:
- Same as GitHub service
- All operations require credentials in request body
- GET requests cannot carry request bodies reliably
- Consistency across all endpoints

**HTTP Method Mapping**:
| Operation Type | HTTP Method |
|----------------|-------------|
| List resources | POST |
| Get/Describe single resource | POST |
| Create resource | POST |
| Update resource | PUT |
| Delete resource | DELETE |
| Invoke (Lambda) | POST |

### 2.4 Service-Specific Route Classes

**Decision**: One route class per AWS service.

**Rationale**:
- AWS services have vastly different operations
- Clear organization and separation
- Matches boto3's service client model
- Independent deployment/testing per service

**Route Classes**:
```
Routes__AWS__Lambda      → /aws-lambda/*
Routes__AWS__S3          → /aws-s3/*
Routes__AWS__IAM         → /aws-iam/*       (Phase 2)
Routes__AWS__CloudWatch  → /aws-cloudwatch/* (Phase 2)
```

### 2.5 Unified Response Schema

**Decision**: All responses follow same pattern as GitHub service, with AWS-specific metadata.

**Response Structure**:
```
Schema__AWS__Response
├── response_context:
│   ├── success        : bool
│   ├── status_code    : Enum__HTTP__Status
│   ├── duration       : float
│   ├── timestamp      : str
│   ├── aws_request_id : str (optional - from AWS response)
│   ├── messages       : List[str]
│   ├── errors         : List[str]
│   └── error_type     : Enum__AWS__Error__Type
└── response_data      : (operation-specific)
```

## 6. Service Layer

### 6.1 Credential Decryption Dependency

```python
class AWS__Client__From__Request(Type_Safe):
    service_encryption : Service__Encryption

    def get_boto3_session(self, request: Schema__AWS__Request__Base) -> boto3.Session:
        # Decrypt secret_access_key
        secret_key_result = self.service_encryption.decrypt_text(
            request.encrypted_secret_access_key)
        if not secret_key_result.success:
            raise ValueError("Failed to decrypt secret_access_key")

        # Decrypt session_token if present
        session_token = None
        if request.encrypted_session_token:
            token_result = self.service_encryption.decrypt_text(
                request.encrypted_session_token)
            if not token_result.success:
                raise ValueError("Failed to decrypt session_token")
            session_token = str(token_result.decrypted)

        # Create boto3 session with credentials
        return boto3.Session(
            aws_access_key_id     = str(request.access_key_id),
            aws_secret_access_key = str(secret_key_result.decrypted),
            aws_session_token     = session_token,
            region_name           = str(request.region)
        )

    def get_lambda_client(self, request):
        return self.get_boto3_session(request).client('lambda')

    def get_s3_client(self, request):
        return self.get_boto3_session(request).client('s3')
```

## 7. Error Handling

### 7.1 boto3 Exception Mapping

```python
def _handle_aws_error(self, error: Exception, response_context: Schema__AWS__Response__Context):
    error_code = getattr(error, 'response', {}).get('Error', {}).get('Code', '')

    mapping = {
        'InvalidClientTokenId'      : (Enum__HTTP__Status.UNAUTHORIZED_401, Enum__AWS__Error__Type.INVALID_CREDENTIALS),
        'ExpiredToken'              : (Enum__HTTP__Status.UNAUTHORIZED_401, Enum__AWS__Error__Type.EXPIRED_CREDENTIALS),
        'AccessDenied'              : (Enum__HTTP__Status.FORBIDDEN_403, Enum__AWS__Error__Type.ACCESS_DENIED),
        'AccessDeniedException'     : (Enum__HTTP__Status.FORBIDDEN_403, Enum__AWS__Error__Type.ACCESS_DENIED),
        'ResourceNotFoundException' : (Enum__HTTP__Status.NOT_FOUND_404, Enum__AWS__Error__Type.RESOURCE_NOT_FOUND),
        'NoSuchBucket'              : (Enum__HTTP__Status.NOT_FOUND_404, Enum__AWS__Error__Type.RESOURCE_NOT_FOUND),
        'NoSuchKey'                 : (Enum__HTTP__Status.NOT_FOUND_404, Enum__AWS__Error__Type.RESOURCE_NOT_FOUND),
        'Throttling'                : (Enum__HTTP__Status.RATE_LIMITED_429, Enum__AWS__Error__Type.THROTTLING),
        'TooManyRequestsException'  : (Enum__HTTP__Status.RATE_LIMITED_429, Enum__AWS__Error__Type.THROTTLING),
        'ServiceUnavailable'        : (Enum__HTTP__Status.SERVER_ERROR_500, Enum__AWS__Error__Type.SERVICE_UNAVAILABLE),
        'ValidationException'       : (Enum__HTTP__Status.BAD_REQUEST_400, Enum__AWS__Error__Type.VALIDATION_ERROR),
    }

    status, error_type = mapping.get(error_code, 
        (Enum__HTTP__Status.SERVER_ERROR_500, Enum__AWS__Error__Type.AWS_API_ERROR))

    response_context.status_code = status
    response_context.error_type  = error_type
    response_context.errors.append(Safe_Str__Text(str(error)))

    # Extract AWS request ID if available
    request_id = getattr(error, 'response', {}).get('ResponseMetadata', {}).get('RequestId')
    if request_id:
        response_context.aws_request_id = request_id
```

## 8. Client Library

### 8.1 QA__AWS_Client (For Testing)

Similar to `QA__GitHub_Secrets_Client`:

```python
class QA__AWS_Client(Type_Safe):
    http_client       : QA__HTTP_Client
    access_key_id     : str
    secret_access_key : str
    session_token     : str = None
    region            : str = 'us-east-1'
    account_id        : str = None

    @cache_on_self
    def server_public_key(self) -> str:
        response = self.http_client.get('/encryption/public-key')
        return response.json().get('public_key')

    @cache_on_self
    def encrypted_secret_access_key(self) -> str:
        # Encrypt locally using NaCl
        public_key_hex   = self.server_public_key()
        public_key_bytes = bytes.fromhex(public_key_hex)
        sealed_box       = SealedBox(PublicKey(public_key_bytes))
        encrypted        = sealed_box.encrypt(self.secret_access_key.encode('utf-8'))
        return base64.b64encode(encrypted).decode('utf-8')

    @cache_on_self
    def encrypted_session_token(self) -> str:
        if not self.session_token:
            return None
        # Same encryption pattern
        ...

    def _base_payload(self) -> dict:
        return {
            'access_key_id'               : self.access_key_id,
            'encrypted_secret_access_key' : self.encrypted_secret_access_key(),
            'encrypted_session_token'     : self.encrypted_session_token(),
            'account_id'                  : self.account_id,
            'region'                      : self.region,
        }

    # Lambda operations
    def lambda_list(self) -> dict:
        payload = {**self._base_payload(), 'request_data': {}}
        return self.http_client.post('/aws-lambda/list', json=payload).json()

    def lambda_invoke(self, function_name: str, payload: dict = None) -> dict:
        request_payload = {
            **self._base_payload(),
            'request_data': {
                'function_name': function_name,
                'payload': payload
            }
        }
        return self.http_client.post('/aws-lambda/invoke', json=request_payload).json()

    # S3 operations
    def s3_list_buckets(self) -> dict:
        payload = {**self._base_payload(), 'request_data': {}}
        return self.http_client.post('/aws-s3/list-buckets', json=payload).json()

    def s3_get_object(self, bucket: str, key: str) -> dict:
        request_payload = {
            **self._base_payload(),
            'request_data': {'bucket': bucket, 'key': key}
        }
        return self.http_client.post('/aws-s3/get-object', json=request_payload).json()
```

## 12. Security Considerations

### 12.1 Credential Handling

- Secret keys exist only in memory, never logged
- Plaintext `access_key_id` enables audit logging without security risk
- NaCl keys rotate on each deployment
- Credentials are not stored server-side

### 12.2 Request Validation

- All inputs validated via Type_Safe schemas
- Safe primitives prevent injection attacks
- Invalid credentials fail fast with clear error types

### 12.3 AWS Permissions

- Server Lambda needs **zero** AWS permissions for target accounts
- All operations use caller-provided credentials
- Server only needs permissions for its own infrastructure (logs, etc.)
